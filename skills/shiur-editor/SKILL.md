# Shiur Editor — עריכת שיעור באורך מלא

מטרה: להפוך תמלול גולמי של שיעור / הרצאה / דרשה (לרוב תמלול אוטומטי עם חותמות זמן,
מילות מילוי ושגיאות תמלול) למסמך עברי ערוך, קוהרנטי ומקצועי — **בלי לצמצם נושאים**.

## עיקרון יסוד: עריכה, לא סיכום

זה **לא** סיכום ולא קיצור. כל רעיון, כל נושא משני, כל מקור, כל משל וכל דוגמה
מהמקור — **נשמרים**. ההיקף של התוצר דומה להיקף המקור. מותר ורצוי:
- להסיר חותמות זמן (כמו `0:1717 שניות`), כפילויות מילוליות, גמגומים ומילות מילוי
- לתקן שגיאות דקדוק, כתיב, תחביר ושיבושי תמלול
- לארגן את אותו תוכן עצמו במבנה לוגי

אסור: להשמיט נושא, לקצר רעיון, "לדלג על החלק הפחות חשוב", או לכווץ דוגמאות.

## הוראות העריכה (קבועות)

1. **עריכה לשונית מקצועית** תוך שמירה קפדנית על המשמעות המקורית.
2. **עברית תקנית, זורמת וברורה.**
3. **שמירה על כל הרעיונות והנושאים המרכזיים** מהטקסט המקורי.
4. **תיקון שגיאות** דקדוק, כתיב וסגנון — בלי לשנות תוכן.
5. **ארגון לוגי וקוהרנטי** של המידע.
6. **כותרות ותת-כותרות** מתאימות לכל נושא.
7. **חלוקה היררכית הגיונית** (H1 ראשי, H2 משני, H3 משנה-משני).
8. **כל פסוק מהתנ"ך נכתב במלואו עם הניקוד המלא.**
9. **צירוף המקור המדויק** (ספר, פרק, פסוק). פורמט:
   `"בְּרֵאשִׁית בָּרָא אֱלֹהִים אֵת הַשָּׁמַיִם וְאֵת הָאָרֶץ" (בראשית א,א)`
10. **גוף ראשון** — כאילו המשתמש מעביר את ההרצאה בעצמו.

## פסוקים — דיוק קריטי (IRON RULE)

- כל פסוק תנ"כי בשיעור → לזהות, ולכתוב אותו **במלואו ובניקוד מדויק** לפי נוסח המקרא,
  גם אם בתמלול הוא משובש (תמלול אוטומטי מסלף פסוקים). מתקנים לנוסח המקורי.
- בתוך ציטוט פסוק, שם הוי״ה נכתב `ה'` (לא הטטרגרמטון המנוקד).
- אם יש ספק בניקוד מדויק — לוודא מול נוסח המקרא, לא לנקד "בערך".
- ציטוטי חז״ל / זוהר / ראשונים שאינם פסוק: לצטט בלשון מכובדת; אם הציטוט אינו
  מילולי-ודאי, להציג כפרפראזה ("תוכן דבריו: ...") ולא במרכאות מדויקות.

## פלט Markdown — מבנה

קובץ `.md` בעברית, עם:
- `# כותרת ראשית` — תיאורית, תואמת לתוכן (תהפוך לשם הקובץ). **חריג: אם המקור
  הוא קישור יוטיוב, הכותרת חייבת להיות הכותרת המדויקת של הסרטון** (כפי שהתקבלה
  מ-`fetch_youtube_transcript.py`), לא כותרת מורכבת מהתוכן.
- **אם המקור הוא יוטיוב:** מיד אחרי שורת ה-`# <כותרת>`, שורה נוספת בפורמט קבוע:
  `מקור: <YouTube URL>`. זהו marker קבוע ש-`build_docx.py` מזהה ומרנדר כשורת
  מקור ממורכזת מתחת לכותרת (לא כפסקת גוף רגילה) — הקישור עצמו יוצא כהיפרלינק
  אמיתי ולחיץ (עם קו תחתון, שחור לפי כלל השחור-לבן — לא כחול). לא להוסיף שורה
  כזו כשאין מקור יוטיוב.
- `## תת-כותרת` לכל נושא, `### ` לתת-נושא.
- פסוקים בתוך `> ` (blockquote) — כל פסוק בשורה משלו, פורמט מנוקד + מקור בסוגריים.
- רשימות עם `- ` או `1. ` לפי הצורך.

## נתיבי הסקריפטים — פותרים פעם אחת

כל הסקריפטים יושבים ב-`scripts/` **של הסקיל הזה**. אל תכתוב נתיב מוחלט מהזיכרון,
ואל תסמוך על `~` בשורת הפקודה — PowerShell ו-cmd ב-Windows לא מרחיבים `~` בתוך
מרכאות, ואז הנתיב מגיע ל-Python כמו שהוא ונכשל.

פתור אותו פעם אחת, וההרחבה תיעשה בתוך Python — זהה ב-Windows, ב-macOS וב-Linux
ובכל מעטפת:

```bash
python -c "import os;print(os.path.expanduser('~/.claude/skills/shiur-editor/scripts'))"
```

בהמשך הקובץ הנתיב שהודפס מסומן `<SCRIPTS>`. **החלף אותו בערך האמיתי בכל פקודה** —
אל תריץ את המחרוזת `<SCRIPTS>` כמו שהיא.

אם הסקיל הותקן במקום אחר (למשל ב-`.claude/skills/` של פרויקט) — השתמש בתיקייה שממנה
נטען קובץ ה-SKILL.md הזה, לא בנתיב שלמעלה.

## בדיקת התקנה — פעם ראשונה בלבד

לפני הריצה הראשונה במכונה חדשה:

```bash
python "<SCRIPTS>/preflight.py"
```

הסקריפט מדפיס דוח בעברית ומחזיר קוד יציאה 0 רק אם הליבה תקינה
(Python 3.8+, `python-docx`, ו-`hebrew_docx_template.py` הצמוד). רכיבים אופציונליים
(yt-dlp, youtube-transcript-api, ffmpeg, faster-whisper, סקיל youtube-transcript)
מדווחים בנפרד ולא מפילים את הבדיקה — כל אחד נדרש למסלול אחד בלבד.

**אם הבדיקה נכשלת — למסור למשתמש את שורות ה-`XX` כמו שהן ואת פקודת ההתקנה
שהודפסה, בעברית. לעולם לא להדביק לו stack trace.** אחרי שהוא מאשר, להריץ את
פקודת ההתקנה ולהריץ את הבדיקה שוב.

התלויות מרוכזות ב-`requirements.txt` שליד ה-SKILL.md. המסלול הנפוץ דורש
`python-docx` (תמיד) ו-`yt-dlp` (ליוטיוב) — התקנה של שניות. רק תמלול Whisper מקומי
דורש את החבילות הכבדות.

## תהליך עבודה (Workflow)

1. **קריאת הקלט.**
   - **אם הקלט הוא קישור יוטיוב:** להריץ
     ```bash
     python "<SCRIPTS>/fetch_youtube_transcript.py" "<youtube-url>"
     ```
     הסקריפט מוריד רק את הכתוביות העבריות (ידניות או אוטומטיות) של הסרטון —
     **בלי** להוריד וידאו/אודיו — ומדפיס `title` / `sanitized_title` / `video_id`
     / `url` / `captions_path` / `transcript_path`. לקרוא את `transcript_path`
     **במלואו** (כמו כל תמלול — ראו למטה), ולשמור את `title` ואת `url` לשימוש
     בשלב 2 (כותרת H1 ושורת "מקור:"). קובץ הכתוביות הגולמי (`.vtt` או `.srt`)
     נשאר בתיקייה כמקור; קובץ ה-`.transcript.txt` הוא ביניים ואפשר למחוק אותו
     בסיום (כמו כל קובץ המרה זמני).

     **אם הסקריפט מדפיס `ERROR` ויוצא בקוד שגיאה** (לרוב: אין כתוביות עברית
     לסרטון, או ש-yt-dlp חסום) — **לא לעצור ולא לשאול.** המסלול הבא הוא סקיל
     `youtube-transcript`, שמגיע באותה חבילה. קודם לוודא שהוא באמת מותקן:
     ```bash
     python -c "import os;p=os.path.expanduser('~/.claude/skills/youtube-transcript/scripts/get_transcript.py');print(p if os.path.isfile(p) else 'MISSING')"
     ```
     - **אם הודפס נתיב** — להריץ אותו, **ברקע** (`run_in_background: true`):
       ```bash
       python "<הנתיב שהודפס>" "<youtube-url>" --lang he
       ```
       הוא מטפס לבד בסולם המסלולים (API → yt-dlp → הסלמת גישה → Whisper מקומי)
       ומדפיס את אותו בלוק `key: value` פלוס `method:`. אם הוא נופל ל-Whisper זה
       ~25 דקות לשעת שיעור (נמדד על מעבד 16-threads; במכונה איטית יותר זה יותר)
       — ולכן ברקע. להשתמש בקובץ ` - טקסט רצוף.txt` שלו כתמלול, ולקחת את `title`
       ואת ה-URL לשלב 2 כרגיל.
       **לדווח למשתמש את `method:`** — אם הוא `whisper`, לציין שהתמלול מקומי ולכן
       ייתכנו שיבושי תעתיק בשמות ובמונחים, שיש לשים לב אליהם בעריכה.
     - **אם הודפס `MISSING`** — **לא לנחש נתיב אחר ולא לקרוס.** להסביר למשתמש
       בעברית ולעצור:
       > לסרטון הזה אין כתוביות בעברית, ולכן צריך תמלול מקומי. הסקיל
       > `youtube-transcript` שעושה את זה לא מותקן אצלך.
       > אפשר: (א) להתקין אותו מדף הבית של החבילה, או (ב) לשלוח לי קובץ תמלול /
       > אודיו של השיעור ואמשיך מכאן.
   - **אחרת:** התיקייה כבר מכילה את קובץ השיעור (DOCX / TXT / תמלול).
     - DOCX: לחלץ טקסט עם `python` + `python-docx`. אם שם הקובץ בעברית גורם
       לבעיית קידוד ב-Windows, להשתמש ב-`glob.glob('*.docx')` במקום לכתוב את
       השם.
   - בשני המקרים: לקרוא את **כל** התמלול עד הסוף לפני שמתחילים לערוך (שיעור =
     לרוב 30-60 דקות, אלפי מילים — לא לערוך מתוך קטע חלקי).
2. **עריכה.** לכתוב את המסמך הערוך המלא ל-`.md` לפי ההוראות וההיררכיה לעיל.
   שם הקובץ = ה-H1 בעברית (שמות קבצים תיאוריים; כשהמקור יוטיוב זו הכותרת המדויקת
   של הסרטון), ליד קובץ המקור.
3. **בניית DOCX.**
   ```bash
   python "<SCRIPTS>/build_docx.py" "<path-to-md>"
   ```
   מפיק `.docx` באותו שם ובאותה תיקייה — RTL מלא, David, שחור-לבן, A4, מספרי עמודים,
   פסוקים מובלטים בהזחה. הסקריפט מסתמך על `hebrew_docx_template.py` **שיושב לידו**
   באותה תיקיית `scripts/` — החבילה עצמאית ואינה דורשת שום קובץ חיצוני.
   **סגנון הבית:** גוף הטקסט, הפסוקים והרשימות ב-14pt ומיושרים לשני הצדדים
   (JUSTIFY); כותרות H2-H4 ב-14pt מיושרות לשני הצדדים; כותרת ראשית H1 ב-16pt
   ממורכזת; הכל David ומודגש בכותרות.

**הדפסה — רק לפי בקשה מפורשת.** לא שולחים להדפסה כברירת מחדל.

- **Windows** (דורש Microsoft Word מותקן — הסקריפט מדפיס דרך Word כדי לשמור על RTL):
  ```powershell
  powershell -File "<SCRIPTS>/print_docx.ps1" -DocxPath "<path-to-docx>"
  ```
  ולאמת עם `Get-PrintJob` שהמשימה נכנסה לתור.
- **macOS / Linux:** אין מקבילה ל-COM של Word, והסקריפט הזה לא ירוץ שם. הדרך
  היציבה היא להמיר ל-PDF ואז להדפיס:
  ```bash
  libreoffice --headless --convert-to pdf "<path-to-docx>" && lp "<שם ה-PDF שנוצר>"
  ```
  אם אין LibreOffice — לומר למשתמש לפתוח את ה-DOCX ולהדפיס ידנית. **לא** לשלוח
  DOCX ישירות ל-`lp`: CUPS לא מרנדר עברית RTL כמו שצריך והפלט יוצא הפוך.

## אם ההיקף חורג מהודעה אחת

שיעור ארוך עלול לחרוג מהודעה אחת. אם לא הצלחת לכתוב את כל המסמך הערוך בבת אחת —
להמשיך בהודעה נוספת בדיוק מהמקום שעצרת (להוסיף ל-`.md` הקיים), בלי לדלג על נושא.

## אימות לפני סיום

- כל נושא מהמקור מופיע בתוצר (סריקה משווה מהירה).
- כל פסוק מנוקד + מקור מדויק.
- ה-DOCX נוצר (גודל > 0).
- שמירת `.md` ליד ה-`.docx` (אותו שם) למקרה עריכה עתידית.
- **אם המקור יוטיוב:** כותרת ה-H1 תואמת בדיוק לכותרת הסרטון ביוטיוב; שורת
  "מקור: <url>" מופיעה מתחת לכותרת גם ב-MD וגם ב-DOCX (ממורכזת, לא כפסקת גוף).
